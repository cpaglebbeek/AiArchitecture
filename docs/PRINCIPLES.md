# Conceptuele Principes — AiArchitecture

## Kernprincipe

> AI is een krachtige junior architect. Geef het een helder kader, en het levert voorspelbare kwaliteit. Zonder kader levert het onvoorspelbare output.

## Afgeleide Principes

### 1. Constraints Before Code
Definieer het kader vóórdat je de eerste regel code schrijft. CLAUDE.md bestanden zijn het equivalent van een architectuurdocument voor de AI.

### 2. Memory is Architecture
Persistent geheugen is geen feature — het is een architectuurbeslissing. Zonder memory is elke sessie een prototype. Met memory bouw je incrementeel.

### 3. Feedback is Learning
Elke correctie die je opslaat als feedback memory maakt het systeem slimmer. Dit is supervised learning op human-in-the-loop niveau.

### 4. WhatIf Before WhatIs
Valideer begrip vóór actie. De kosten van een verkeerde implementatie zijn altijd hoger dan de kosten van een extra validatiestap.

### 5. Multi-Agent is Multi-Perspective
Vier agenten zijn niet vier keer dezelfde output. Het zijn vier perspectieven die elkaar aanvullen en controleren.

### 6. Security is a Constraint, Not a Feature
Beveiliging wordt afgedwongen door constraints (verboden acties, verplichte encryptie), niet door hopen dat de AI het goed doet.

### 7. Evidence Over Theory
Dit framework is niet bedacht aan een whiteboard. Het is gegroeid uit dagelijks gebruik in 50+ projecten. Elke regel bestaat omdat er een concreet probleem was dat het oplost.
